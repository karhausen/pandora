# Pandora Roadmap (ab MVP 25.1.3) 
 
## [[Leitgedanke ]]

Nicht das LLM ist Pandora. 

Pandora ist das System, das entscheidet: 

- welche Informationen benötigt werden, 
- welche Fähigkeiten erforderlich sind, 
- welche Tools benutzt werden, 
- welche Verbesserungen notwendig sind. 

Das LLM ist ausschließlich ein intelligenter Berater. 

Python behält jederzeit die Kontrolle.

# Entwicklungsphasen 
 

## MVP 25.2 
### Context Builder Completion 
 

- Context Ranking

## MVP 25.3 
### Request Interpreter 
 

LLM analysiert ausschließlich: 
 

- Benutzerabsicht 
- benötigte Wissensräume 
- benötigte Tools 
- Confidence 
- Begründung 
 

Keine Ausführung. 
 

--- 
 

## MVP 25.4 
### Capability Analyzer 
 

Erkennt automatisch: 
 

- Tool Gap 
- Knowledge Gap 
- Skill Gap 
- Core Gap 
 

Erzeugt strukturierte Empfehlungen. 
 

--- 
 

## MVP 25.5 
### Python Orchestrator 
 

Validiert sämtliche Empfehlungen. 
 

Prüft: 
 

- Governance 
- Security 
- Policies 
- Profil (local/company/cloud) 
- Berechtigungen 
 

Nur Python entscheidet. 
 

--- 
 

## MVP 25.6 
### Cognitive Context Pipeline 
 

Deterministische Verarbeitung: 
 

- Quellen lesen 
- Ranking 
- Duplicate Removal 
- Budget 
- Prompt Builder 
 

--- 
 

## MVP 25.7 
### Tool Recommendation Workflow 
 

Capability Gap → 
 

Tool Factory → 
 

LLM Code Generation → 
 

Review → 
 

Tests → 
 

Governance → 
 

User Approval → 
 

Registry → 
 

Aktives Tool 
 

--- 
 

## MVP 25.8 
### Knowledge Recommendation Workflow 
 

Automatische Erkennung von: 
 

- fehlendem Wissen 
- veralteten Informationen 
- Dokumentationslücken 
 

Erzeugung von Improvement Proposals. 
 

--- 
 

## MVP 25.9 
### Core Recommendation Workflow 
 

Erkennt Architekturverbesserungen. 
 

Erzeugt: 
 

- Core Proposal 
- Risikoanalyse 
- Auswirkungen 
- Roadmap-Vorschlag 
 

Keine automatische Umsetzung. 
 

--- 
 

## MVP 26 
### Working Memory 
 

Temporärer Denkraum. 
 

Speichert: 
 

- Ziele 
- Hypothesen 
- Zwischenergebnisse 
- offene Fragen 
- Prioritäten 
 

Nach Abschluss: 
 

- verwerfen 
- Learning 
- Long Memory 
- Obsidian 
 

--- 
 
MVP 26.1 – Central Decision Engine

Aufgabe:

sammelt Interpreter-, Analyzer-, Tool-, Knowledge- und Core-Empfehlungen
erzeugt genau eine Entscheidung
erkennt Freigabepunkte
fragt den User nur bei relevanten Entscheidungen
startet nichts automatisch
hält Tool/Core/Knowledge-Prozesse gleichartig

Das fühlt sich für Pandora sehr stimmig an.

---

## MVP 27 
### Adaptive Pandora 
 

Regelmäßige Reviews. 
 

- Tool Reviews 
- Knowledge Reviews 
- Core Reviews 
- Learning Reviews 
 

Erkennt langfristige Verbesserungen. 
 

--- 
 

## MVP 28 
### Controlled Autonomy 
 

Pandora darf: 
 

- analysieren 
- empfehlen 
- vorbereiten 
- testen 
- simulieren 
 

Pandora darf niemals ohne Freigabe: 
 

- Core ändern 
- Releases erstellen 
- Tools aktivieren 
- Policies verändern

Mein Review dazu 😉 

Ich finde, diese Roadmap ist deutlich näher an deiner ursprünglichen Vision 
als die vorherige. Der größte Unterschied ist, 
dass Pandora jetzt nicht mehr um einzelne Features herum wächst, 
sondern um einen Entscheidungsprozess. 

Ein Punkt würde ich allerdings bewusst noch offenlassen und erst später 
implementieren: den Request Interpreter. 
Ich würde ihn von Anfang an als generischen “Cognitive Planner” entwerfen, 
sodass er nicht nur Quellen und Tools empfiehlt, sondern künftig auch Ziele, 
Risiken und Strategien beurteilen kann. 
Dann muss diese zentrale Komponente später nicht noch einmal grundlegend umgebaut werden. 
Ich vermute, dass genau dort langfristig das eigentliche “Denken” von Pandora stattfinden wird.
